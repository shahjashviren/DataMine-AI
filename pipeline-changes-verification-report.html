Change 1 — Replace arXiv → Wikipedia REST + Semantic Scholar ×2

Change 1arXiv removed; Wikipedia uses /api/rest_v1/page/summary/{title}Done

What changed in collector.py: Removed _fetch_arxiv() and ARXIV_API entirely. _fetch_wikipedia() now calls the MediaWiki search endpoint to get page titles, then fetches each page via the REST Summary API (/api/rest_v1/page/summary/{title}) — clean plain-text, no HTML parsing.

Two S2 queries per intent query: For each of the 3 intent queries, S2 is called twice — once with the query verbatim (S2-A) and once with a complementary rephrasing built by _make_s2_query_b() (S2-B). This guarantees overlapping results for the deduplicator.

User-Agent on every request: A module-level _HEADERS = {"User-Agent": "DataMineAI/2.0 ..."} dict is passed to every requests.get/post call — Wikipedia, Wikimedia Commons, Semantic Scholar, Openverse.

Change 2 — Chunking Multiplication Fully Tracked

Change 2Explicit factor logging + RuntimeError if parent_document_id missingDone

What changed in cleaner.py: clean_data() now checks every output entry for parent_document_id after cleaning. If any entry is missing it, it raises RuntimeError immediately — the bug can never pass silently.

Logging: The multiplication factor is explicitly printed on every run so it's visible in pipeline.log:

Run 1: 54 raw entries -> 171 chunks (factor 3.17x — each chunk carries parent_document_id,
        dedup will skip intra-doc comparisons).
Run 2: 22 raw entries -> 24 chunks (factor 1.09x — ...)

Invariant verified: Both runs: missing parent_document_id = 0. No intra-doc dup pairs flagged.

Why chunks can exceed raw count: Wikipedia article extracts are often longer than _MAX_CHUNK_CHARS (1 000 chars). Those are split by the existing chunker, with each chunk tagged to its source page via parent_document_id = "wiki:{page_id}". The deduplicator skips any pair sharing the same parent.

Change 3 — Stricter Relevance Filter (Text + Images)

Change 3YES/NO specificity gate replaces 1-10 scoring; image Groq title check addedDone

Text prompt rewrite: Replaced the 1-10 scoring rubric with a binary YES/NO prompt. The exact question asked is:

YES — the text is SPECIFICALLY and DIRECTLY about "{topic}", not merely about a
      broader category, an adjacent technology, or general infrastructure that
      could apply to many unrelated fields.
NO  — the text is off-topic, uses the same words in a different domain, or is
      only tangentially related.

Image Groq filter (new): After the heuristic pre-filter, all titled images are now passed to Groq for a YES/NO relevance check on their title + tags. Untitled images pass through. Evidence from Run 1:

[img DROP] Memorial Truck 9/11 (Scroll Down)
[img DROP] USACE, EUCOM break ground on first of 10 fire station renova...
[img DROP] SoCal Freight Graffiti Benching (11-02-2020) ×6
[img KEEP] Container trucks on an American highway
[img KEEP] Introduction to Transportation Management Systems (TMS)...
[img KEEP] Freight Management: Streamlining Your Supply Chain Operations

Run 1 image filter: 61 in → 36 out (41% dropped). Run 2: 40 in → 25 out (38% dropped).

One Known Issue

Semantic Scholar's free tier hit a 429 rate-limit on both test runs (daily quota). This is an external API constraint, not a code bug — the retry logic is correct and Wikipedia fills the gap. When the S2 quota resets the two-query strategy will produce the intended overlapping academic papers.
